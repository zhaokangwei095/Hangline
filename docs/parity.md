# 与 macOS 原版的差异

移植不是逐行翻译。这里记录每一处 Windows 做不到、或者做法不同的地方——**包括做得
更好的地方**，避免这份清单变成一份借口。

## 1:1 照搬

绳子抛物线垂弧、卡片布局两分支、容量与滚动、夹子/玻璃框/徽标的所有尺寸与颜色、
弹簧与摆动的全部参数、单击复制 / 双击打开 / 长按 / 拖出、托盘菜单项、全局热键、
以英文原文作为本地化 key 的做法。

三条容易漏掉、因此专门确认过的小行为：

- **在顶边点一下会把绳子收回去**，并且直到指针离开这条带都不再下来（原版
  `menuBarSuppressed`）。Windows 上带内是穿透的，收不到鼠标事件，所以用 30 Hz 的
  光标轮询去读按键状态，取的是 `GetAsyncKeyState` 的"自上次调用后按下过"那一位——
  直接看当前按下状态会漏掉两次轮询之间的那一下。
- **绳上超过一屏时，卡片之间的缝隙也接收指针**，这样滚轮不用瞄准某张图（原版
  `updateMousePassThrough` 里那段 band 兜底）。它只在"绳上保留"设了固定数量时生效：
  选"放得下多少算多少"时永远不会溢出，缝隙就该继续穿透。
- 剪贴板监听比原版**更好**：macOS 那边没有变更通知，只能 0.5 秒轮询；Windows 有
  `WM_CLIPBOARDUPDATE`，是即时的。

- **剪贴板的过滤条件改过两次。** 原本"复制里带文字就不算这张图是想收藏的"，实测发现
  从浏览器 / Word / PDF 复制图片时，剪贴板里一定还带着来源 URL 或周边文字，于是这条
  规则把最常见的用法全杀了——先改成只看文字。然后"带文件就不挂"这一条也被推翻了：
  原版（`ClipboardWatcher.swift`）拒绝 `.fileURL`，在 macOS 上说得通，但 Windows 上
  在资源管理器里复制一张图是最自然的"把它挂上去"的动作，托盘里那句"挂上复制的图片"
  不挂它就等于撒谎。现在带文件时把其中是图片的那些**按原文件**挂上（不另存副本，
  附带进来的缩略图位图忽略），非图片文件仍然不挂。
  另外一次复制会连发几条通知，第一条常常还读到上一张图，被去重逻辑当成重复丢掉——
  所以读取挪到"最后一次通知之后 100ms"，并对 `CLIPBRD_E_CANT_OPEN` 重试几次。

## 移植时"接错了线"的三处（已修，记在这里免得再犯）

这三处都不是 Windows 做不到，是我把行为搬过来时接断了，而且**都不会报错**，所以
看起来就像"功能存在但没反应"：

- **整层悬停反馈是死的。** `CardView` 自己 new 了一份 `CardMotion`，而悬停写进的是
  `MotionController` 字典里的那一份，两边永不相交。于是徽标淡入、放大 1.035、阴影
  加深、按压 0.95 一次都没出现过。原版这三条挂在同一个 `hovering` 状态上
  （`PeggedView.swift:97-98,114`），移植时状态源被拆成了两处。
- **"什么时候放绳"曾被做成互斥单选。** 原版是三个独立勾（`AppDelegate.swift:656-673`），
  我用了单选控件：勾了"顶边停留"就把"有新图时"的勾抢走。控件类型本身在撒谎。
- **托盘菜单的 ✓ 画不出来。** `ShowImageMargin = false` 会连勾选列一起压掉，
  所有 `Check`/`Radio` 的状态没有地方显示；另外 `NotifyIcon` 根本不会触发菜单的
  `Opening` 事件（WinForms 文档标 Not applicable），所以"每次打开重建"必须挂在
  右键按下上，否则状态永远停在启动那一刻。

## 比原版多做的一步

原版重启后绳子是空的。这里把上次退出时挂着的文件记在 `settings.json` 里，启动时
原样挂回来（文件已被删掉的自动跳过）。代价是多了一个持久化点，所以退出时的保存
不再看窄条窗口是否可见——它在绳子收起时是隐藏的，用可见性判断会丢掉最后一次挂图。

## 偏离原版的一处：新图挂上后绳子等你看完再收

原版 `AppDelegate.swift` 里 `peeksAtNew` 是 `reveal(peekFor: 2.5)`，且收回只看
`now < peekUntil`：指针不在面板里就开始走 `retractDelay`(0.25 s)。Windows 上照搬
+这一条的实测结果是——**绳子确实下来了，但 2.5 秒后就收回，而复制图片时指针在
浏览器或桌面里，从键盘移到屏幕顶部早就超过 2.5 秒**，抬头看时绳子已经不在，
观感就是"挂上了但绳子没弹出来"。

所以这里做了三处偏离，全部记在 `RevealController` 里：

- `PeekSeconds` 2.5 → **6**。6 秒足够把手移到鼠标上再移到屏幕顶部。
- peek 期间指针**没来过**绳子之前，`_away` 不计时（原版是立即开始计）。来过了才
  恢复正常规则——否则"看了一眼就走"和"根本没看"无法区分。
- 兜底：指针始终没来，`PeekSeconds + PeekGrace`(4 s) 后无论如何收回。没有这条，
  一次没人看的 peek 会让绳子一直挂在用户没要求的屏幕上。

`_peeking` 这个状态是必需的：`_peekUntil` 初始值是 `double.NegativeInfinity`，
只靠它判断会把每一次普通的顶边停留都当成"没人看的 peek"而挡住——第一版就这么写，
三个既有 reveal 测试当场全红。

原版的 2.5 秒在 macOS 上说得通：菜单栏常驻可见，指针本来就在屏幕顶部附近。
Windows 的触发带只有 6 像素高，指针的位置和复制动作的位置没有关系。
## 降级

### 玻璃材质没有真背景模糊

原版用 `.ultraThinMaterial`，会实时模糊卡片后面的桌面。Windows 没有受支持的
跨进程背景模糊 API（Aero 毛玻璃早已移除，Mica 只能由 WinUI 3 的窗口背景使用，
而我们要的是逐像素透明的置顶条）。

现在：半透明渐变 + 高光内描边 + 外描边近似。**几何、描边、阴影、圆角全部精确照搬**，
差的只是"透出后面的东西被磨平"这一层。

### 无法接管系统截图设置

原版会改 `com.apple.screencapture` 的落盘位置、关掉浮动缩略图，退出时还原。
Windows 没有受支持的接口能改截图工具的落盘位置。

现在改成三件事叠加，达到同样的使用结果：

1. **自建截图**（`Ctrl+Alt+Shift+A/F/W`）直接写进自己的收件夹——这条是真的
   "拍下的瞬间即挂上绳、完全跳过桌面"，没有任何中间环节；
2. **监听** `图片\Screenshots`、`视频\Captures`、桌面与用户额外添加的文件夹，
   所以你用 `Win+Shift+S`、微信、QQ 截的图一样会挂上。
3. **抢下 `PrtSc` 这个键**：勾选"接管截图"时把它注册成"拖框截图"，按一下即选区、
   截完挂上绳。这是 Windows 上最接近原版"截图这件事归我管"的做法。注册失败（被
   OneDrive、截图工具或键盘驱动抢先）只记日志，不影响其余功能。

   这一条**尚未由真人按键验证**：Windows 会忽略注入的 `VK_SNAPSHOT`，所以自检脚本
   按不动它（同一批热键里 `Ctrl+Alt+Shift+F` 是注入成功并实测挂图的，机制本身没问题）。
   注册本身在日志里可查（`hotkey PrtSc -> id …`）。

浮动缩略图这一项在 Windows 上不适用（系统没有这个东西）。

### 拖框截图那一层：冻住的一屏，不是活的透明层

原版这层是实时透明的（底下的画面还在动，只是变暗）。WPF 在
`AllowsTransparency = false` 时**整个忽略** ARGB 的 alpha，
`Color.FromArgb(90, 0, 0, 0)` 因此渲染成不透明的黑——第一版就栽在这行，按下
`PrtSc` 看到的是一整块黑屏。逐像素透明能做到实时，代价是整块屏幕交给软件渲染。

现在改成：窗口出现**之前**先把这一屏抓一张图当背景，遮罩画在它上面。代价是
**选区期间屏幕是冻住的**。抓来的图只用于显示——真正保存的像素在选区结束后另抓
一次，所以成品里不会带遮罩自己。实测（2560×1600）：桌面亮度均值 40.7，遮罩下
17.7，纯黑像素 0.0%。

### 拖到回收站由 shell 完成

原版必须自己实现删除，因为 macOS 只"告知"拖到了废纸篓。Windows 上把文件
`DragDropEffects.Move` 拖到回收站，shell 自己就删了。

结果语义相同（卡片随后掉落），但实现上我们不做"回收站图标矩形命中检测"——
那个依赖半公开的 `IFolderView2` 接口，脆弱且没有收益。

### 长按的「标记」编辑器：重建，不是降级

macOS 有系统共享扩展 `com.apple.MarkupUI.Markup`，并且能拿到"用户保存了"的回调。
Windows 没有等价 API：任何外部编辑器都不会通知你。

所以这里自己写了一个（`Overlay/AnnotationDoc.cs` + `AnnotatorWindow.cs`）：
矩形、箭头、画笔、文字、马赛克五种，四种颜色，撤销/重做，`Ctrl+Z` / `Ctrl+Y`，
`Enter` 保存、`Esc` 放弃。保存按**原图像素尺寸**重新渲染后原子写回，卡片不换 id、
原地换图——和原版的闭环一致。

标记点存的是图像像素坐标而不是屏幕坐标，这样屏幕上看到的和写进文件的不可能
差一个缩放系数。右键菜单里的「标记」和长按走同一条路。

「在画图里打开」仍然保留为兜底；`Actions.Annotate` 里如果编辑器构造失败会自动
退回它，而不是让长按这个手势哑掉。

### 录屏剪辑：换成了 ffmpeg，因为系统 API 够不到

原计划用 Windows 自带的 `Windows.Media.Edit.VideoEditingService`（照片应用背后的
那个裁剪服务，`Auto` 档免重编码）来对应原作的
`AVAssetExportSession(Passthrough)`。

**实测结论：这个 API 从 .NET 8 WPF 里调不到。** `Windows.Media.Edit` 不在 .NET
为 WinRT 生成的投影命名空间里，把目标版本从 `10.0.19041` 提到 `10.0.22621` 也一样。

所以改成：探测系统里已有的 ffmpeg，用 `-ss/-to -i … -c copy` 做同样的免重编码流拷贝；
**绝不捆绑、也不下载**。这台机器实测把一段 672MB 的录屏裁成 3.08 秒 / 6.5MB。
探测不到 ffmpeg 时，剪辑窗口会明说"这台电脑上没有 ffmpeg，剪不了这段"，并把按钮
变成「打开」交给系统播放器——而不是假装保存成功了。

### 绳子只会停在启动那一块屏上（曾漏掉，现已按原版每帧换屏）

原版每个 tick 都重算指针下的屏幕，换屏就搬家：

```swift
if panel.screen != screen { panel.placeOnScreen(); updateCapacity() }
```

`AppDelegate.swift:481-500`，且 `:188` 的注释专门点出这个场景——*"it also works
when another display sits above and the pointer never stops"*：另一块屏摆在上方时
指针根本不会停留，所以每帧换屏是必须的，不是优化。

这里一度漏了整条规则：`_monitor` 在 `SourceInitialized` 里按光标选一次屏，之后永远
是那块。`OnPoll` 里的 `inBand` 判定写的是 `cursorY <= _monitor.Bounds.Y + BandDepth`，
所以外接屏顶边永远不触发——**把手停麻了绳子也不会下来**。`BlockedByFullScreen`、
`WindowRectPhysical`、卡片坐标换算全绑在同一块屏上。

修法（`LineWindow.FollowCursor`，每帧一次）：

- 收起状态跟随光标换屏，和原版一致；
- 绳子**放着的时候不换**：正看着照片把它瞬移到另一块屏会把卡片从指针底下拽走；
- 动画进行中不换，否则放绳/收绳会被拦腰切断；
- `--pin` 时不换，那是开发期故意把绳子按住的手柄；
- 截图时按 `captured` 矩形反查屏幕（原版 `hangCapture` 的做法），否则在外接屏上截的
  图会领着主屏顶上的绳子 peek。

规则本身放在 `Core/LineRules.ShouldFollowScreen`，`LineRules` 是纯函数、可单测；
`LineWindow` 只负责触发。多屏几何用一个 2560×1600 双屏（第二块在左，负 X）的探针
验过：按各自屏幕边界判定，左屏顶边不再被判到主屏以外。

**未由真人验收**：这台机器只接了一块屏，双屏行为是用合成几何验的，插上外接屏请按
`docs/manual-test.md` 走一遍。

## 适配（Windows 上本来就没有对应物）

| 原版 | 这里 |
|:--|:--|
| 指针停在菜单栏 | 指针停在屏幕最上边缘 6 物理像素带内，停留 0.25 秒 |
| `CGSCopyManagedDisplaySpaces` 判断全屏 Space | `SHQueryUserNotificationState` + 前台窗口 `DWMWA_EXTENDED_FRAME_BOUNDS` 是否铺满监视器（粒度比 Space 粗） |
| `SMAppService` 开机自启 | `HKCU\...\Run`（免签名） |
| 系统 `Tink` / `Pop` 音效 | 启动时在内存合成同样时长的短音；丢弃播系统回收站音 |
| 强力点按 → Quick Look | 没有"用力按"这个手势：中键点击或右键「快速查看」打开自建的铺满屏幕的原图查看（`←` `→` 在绳上的图之间走，`Esc` 放回），双击仍然是默认程序打开 |
| 9 种语言 | 中文 + 英文（结构留好，其余是纯翻译工时） |
| 「检查更新」打开官网 | 砍掉：本项目没有官网，程序也始终不联网 |

## 快捷键为什么带 Shift

原版是 `⌃⌥T`，这里保留 `Ctrl+Alt+T`。但自建截图的三个键最初选的是
`Ctrl+Alt+A/F/W`，实测 **`Ctrl+Alt+A` 已被微信截图占用**，`F` 和 `W` 也被别的
程序占了。抢别人已经注册的键会产生一个看起来坏掉的快捷键，比按起来长一点更糟，
所以自建截图统一加 Shift，并在日志里记下注册失败的键。
